```markdown
## Problem
Project activity emails repeatedly interrupt project members. There is
currently no way to stop those emails for a specific project without
affecting anything else.

## Proposed outcome
A project can be put into an email-muted state. Members of that project
stop receiving activity emails for it.

## Acceptance
1. A project can be placed into a distinct muted-email state.
2. While a project is muted, its members receive no activity emails for
   that project.
3. While a project is muted, members still receive in-app notifications
   for that project's activity, unchanged.
4. Muting one project has no effect on email or in-app notifications for
   any other project, and no effect on any global notification setting.

## Constraints
- Only the email channel is affected; in-app notifications and global
  notification settings are unaffected by design intent.
- Scope is a single project at a time.

## Out of scope
- Providing a way to unmute a project once muted.
- Any change to in-app notification behavior.
- Any change to global notification settings.
- Notification channels other than email and in-app.

## Value case
Beneficiary: members of a project whose activity email volume is
disruptive. Urgency: interruption is ongoing today. GO — reduces
interruption while preserving visibility (in-app stays intact) and
without touching other projects or global settings.

## Open questions
- none
```
