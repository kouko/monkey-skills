## Problem

When a branch's changed files are documentation, the review loop confirms the
diff and misses the document. Two measured consequences, each observed
independently on two branches:

1. **A claim outside the diff is invisible.** Six consecutive diff-scoped
   review rounds missed an instruction that had been wrong since before the
   branch existed; it was found the first time a round was dispatched to read
   the whole file (audit §2). A document has no tests, so an unchanged line is
   only an untouched line, not a correct one.
2. **The defect classes that matter for prose are not dimensions.** Five of the
   ten code-shaped dimensions returned vacuous PASS on every docs round in both
   sessions; the checks that actually caught defects — citation resolution,
   absolutes, population statements, cross-paragraph contradiction — were
   hand-written into the dispatch prompt every round, by two operators
   independently (audit §3.3).

Meanwhile the highest-volume mechanical defect — a `path:line` citation whose
pointer drifted — recurs constantly (four measured instances on one branch,
nine invalidated pointers in a single insertion on the other) and is verified
today by ad-hoc throwaway scripts rewritten each session.

## Users

- The **orchestrator** running `finishing-a-development-branch` /
  `requesting-code-review` on a docs-only branch — any tier; the dispatch text
  must not require judgment to apply.
- The **reviewer subagents** receiving the dispatch — they need the prose
  defect classes named, not implied.
- The **operator (kouko)** reading verdicts — stops paying for hand-writing the
  same four instructions every round, and for re-deriving citation verification
  per session.

## Smallest End State

Two deliverables, one branch:

1. **`loom-code/scripts/check_doc_citations.py`** (name final at plan time) —
   stdlib-only, read-only. v1 checks exactly two things, both live-tested on
   the 9-round branch (audit §5: 45 citations verified in one command; two
   defect classes permanently retired):
   - every `` `path:line` `` / `` `path:line-range` `` citation in the target
     docs resolves to a file that exists and a line within its length;
   - every `` §N `` / `` §N.M `` anchor into a named sibling document resolves
     to an existing numbered heading there.
   Explicitly **not** in v1: quoted-string grep (uncured false-positive
   surface, never live-tested), semantic claim checking (research: nobody has
   mechanised it; it stays with the reviewer).
2. **A docs-only dispatch mode in `requesting-code-review`** — one in-place
   amendment at the diff-scope step (`SKILL.md:96` region): when every changed
   file is documentation, (a) reviewers read the **whole changed artifact**
   with the diff as context, not the reverse; (b) the dispatch carries the
   prose defect taxonomy — omission / ambiguity (unsupported absolutes) /
   inconsistency (cross-paragraph, changed-vs-unchanged) / incorrect-fact
   (citation does not support the claim) / missing population on any measured
   number; (c) the citation script's output rides the dispatch packet.
   The code-shaped dimensions stay untouched for code branches; the
   `code-reviewer.md` agent contract and its ten dimensions are **not**
   modified (rounds 7–9 proved the dispatch prompt alone suffices).

## Alternatives Considered (Axis 4 — researched, four dispatched agents, EN+JA)

| Alternative | Who ships it | Why rejected here |
|---|---|---|
| Embed content instead of citing (`literalinclude`, mdBook `{{#include}}`, doctests) — drift becomes a build failure | Rust Book, rustc-dev-guide CI [EN, primary] | Conflicts with the family's test-pinned pointer-not-copy convention for prose→prose; no Sphinx/mdBook infra in repo |
| Prose linters with custom rules (Vale, textlint) | Vale/textlint ecosystems [EN+JA] | Lexical only — can flag the word "only", cannot check its truth; new toolchain dependency for less than the custom script does |
| Link checkers (lychee, markdown-link-check, Sphinx -n) | Rust Book CI et al. [EN, primary] | URL/xref surfaces only; none parses `path:line` into a bounds check |
| Full prose-taxonomy into `code-reviewer.md` agent contract as new dimensions | — | Bigger blast radius than proven necessary — rounds 7–9 achieved detection through dispatch text alone; agent contract stays stable for code branches |
| Reading-technique swap (PBR roles) | Basili et al. [EN, primary; contested replications] | Evidence contested (2006 replication, Laitenberger 69% vs 70%); dominant variable is likely task expertise, not technique |

**My take**: custom ~150-line stdlib script + dispatch-layer paragraph.
**Why**: matches the repo's existing guard-script convention (zero new
dependencies), both halves carry live-test evidence from this week, and
industry research confirms the semantic layer cannot be mechanised — so the
mechanical layer should be exactly as large as what was proven, and no larger.
**Conditional reversal**: if the corpus run shows the two v1 checks
false-positive above roughly one in ten hits after legitimate-pattern
exclusions, stop and reassess the citation grammar before shipping the mode
that depends on it.

## What Becomes Obsolete

- Per-session ad-hoc citation verification (three ~20-line throwaway scripts
  written in one session alone) — replaced by the script.
- The hand-written four-instruction block both operators added to every docs
  review dispatch — codified by the mode.
- Audit §3.1 and §3.3 change status from PROPOSAL to shipped (the audit file
  itself stays as a dated observation; the resolution is recorded via this
  brief and the close-out).
- `docs/loom/BACKLOG.md` "what 0.39.0 does NOT close" item 3 (citation drift)
  — the detection half is mechanised; annotate the entry at close-out rather
  than deleting it (the prevention half — durable anchors — remains open).

## Decision

Build the two-check citation script and the docs-only dispatch mode as one
branch, wiring the script's output into the mode's dispatch packet. Do NOT
build: quoted-string verification, semantic claim checking, new reviewer
agents, new dimensions in the agent contract, any change to code-branch review
behaviour, any loop-cap change (that is the (P1+P2) slice).

## Dogfood / acceptance design

1. **Script (P3)**: run against the full `docs/loom/{audits,specs,plans}`
   corpus (831 citations). Recall floor: every documented real drift instance
   from the two source branches must be flagged. Precision: manually
   adjudicate all hits; false-positive rate above ~10% after exclusions
   triggers the conditional reversal above. Zero writes to the repo.
2. **Mode (P4)**: planted-defect A/B. Build a fixture docs branch carrying one
   defect per taxonomy class (stale citation / false absolute /
   population-less measurement / cross-paragraph contradiction / omission);
   **mechanically verify the fixture before dispatch** (the
   contaminated-fixture lesson from `2026-07-27` coldread). Dispatch default
   review vs docs-mode review; count classes caught per arm. Weak-tier cells
   n≥2 or direction-only conclusions (run-to-run variance lesson).
3. Order P3 → P4: the corpus run's real drift list feeds the fixture's
   planted-defect material.

## Open Questions

1. Which docs count as "documentation" for mode detection — `*.md` everywhere,
   or `docs/**` + skill `references/**` only? (Plan-time decision; affects
   false-trigger rate on mixed branches. Leaning: all-changed-files-are-`.md`
   is the trigger, path-agnostic.)
2. Does the script run in the orchestrator's dispatch step or as a
   `finishing` verification hook? (Leaning: dispatch step of
   `requesting-code-review` docs mode — single wiring point; finishing
   inherits it via delegation.)
3. §N anchor grammar: numbered headings only (`## 5.` / `### 3.7`), or also
   named anchors? (Leaning: numbered only in v1 — that is what the corpus
   uses.)
