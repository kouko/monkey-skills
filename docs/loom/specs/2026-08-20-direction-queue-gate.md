## Problem

When kouko works across several arcs in one project, work sometimes proceeds against a direction that is no longer true — and he finds out days later. The measured instance: a decision to rescope one milestone part was made, written to a branch, and never merged, so the repository's generated `## Now` line advertised a superseded objective for nine days while three arcs of explicitly-deferred work entered the milestone.

The instinct is that the direction was invisible. It was not. Measured against the transcripts, every one of those conflicts was **detected and reported at the time**:

- The unmerged branch was tabled twice on one day, labelled 「未推」.
- The fourth arc's roadmap conflict was named explicitly at its Axis 0.
- Each arc's overturning of the previous arc's premise was called out as it happened, in strong language.

None of it became a stop. Every flag was one line inside a long status message, and the next human turn was the next design question. In the same message that listed the branch as unpushed, the agent restated the superseded objective three lines above.

So the gap is not detection and not visibility. It is that a detected conflict arrives as a report rather than as a question that must be answered.

## Users

kouko, working in a repo that has a `docs/loom/backlog/` store and a `DIRECTION.md`, opening a new arc — the moment when the cost of proceeding against a stale direction is lowest and the information needed is already on disk.

When [an arc is about to start and the repo's stated queue disagrees with either the work or the merge state], I want [to be stopped and asked one question], so I can [answer once and have the answer recorded, instead of reading a report and moving on].

Not covered: repos without a backlog store or DIRECTION.md — those skip silently, as the existing Axis 0 ready check already does.

## Smallest End State

Two mechanical checks, wired as one blocking gate at arc entry, in the shape the on-ramp choice gate already uses in this repo.

- BI-1 — A check reports every commit reachable from any ref but not from `HEAD` that modifies `docs/loom/DIRECTION.md` or a backlog entry file currently named in `## Now`. Repo state only; no knowledge of conversation required.
- BI-2 — A brief must carry a `## Queue relation` line in a closed grammar declaring how this arc relates to `## Now`: it names a queue entry, declares itself unqueued with a reason, or declares which entry it displaces and why. A missing or malformed line is a violation.
- BI-3 — Both checks run at arc entry and BLOCK. A violation exits with the structurally-distinct code the caller must relay, printing the question verbatim; the caller stops, relays, waits for kouko's answer, and only then writes the answer into the brief. This is the on-ramp gate's contract, reused rather than re-invented.
- BI-4 — The recorded answer is what makes the gate not ceremony: it lands in the committed brief, so a later reader can see the question was asked and how it was answered.
- BI-5 — The progress card's rendered label for the plan's `Goal:` field changes from `goal:` to `end-state:`, because the built-in `/goal` command holds a session-scoped directive and the collision is now visible to the same reader in the same session. Display label only; the plan schema field keeps its name.

## Decision

We build one blocking gate with two triggers, and the card-label rename. We do NOT build the two remedies this arc started out intending, because measurement disqualified them.

- **Rejected — showing the direction on the progress card.** The information was displayed at the time and was itself stale; the correct fact sat three lines away in the same message. A card line would have broadcast the superseded objective with more authority. It becomes worth building only after the gate makes the file trustworthy, and it is recorded in Out of Scope with that precondition.
- **Rejected — forcing a trace when the direction is rewritten.** The agent already did this, well, of its own accord, with the reasoning written down. The trace existed and was then forgotten. Tracing is not the missing part.
- **Chosen — blocking.** The one shape with a working precedent in this repo is the on-ramp choice gate: exit 2, STOP, relay the printed question, wait, record the answer. It works because it refuses, not because it informs.

Scope honesty: the trigger evidence is n=1. Two control projects measured zero instances of both trigger conditions, so in those repos this gate will never fire — which is the intended cost profile, not a defect.

## Alternatives Considered

**My take: Recommend the blocking gate.** Why: it is the only shape with a working precedent inside this repo, and the failure it addresses is specifically that reporting did not work. Conditional reversal: if the gate fires often enough to be answered reflexively rather than considered, it has become ceremony and should be narrowed to the merge-state trigger alone.

| Alternative | Who ships it | Mechanical? | Why not chosen |
|---|---|---|---|
| Status-enum CI enforcement for decision records | ADR practice; a JA practitioner writeup reports 175 trials moving to CI-enforced closed status enums | Buildable, not packaged | Solves "status forgot to update", not "work started against a stale queue". Its enum idea is borrowed for BI-2's closed grammar |
| Doc-vs-code drift detectors (Drift/fiberplane, Roam, ai-blame, Dosu; JA: artgraph) | Real shipped tools | Yes — AST hash or git-blame age | They detect documentation stale against CODE. Our staleness is against an unmerged DECISION, which no hash of the current checkout can see |
| WIP limits / Definition of Ready / Jira sprint-scope warnings | Scrum and Jira practice | No — ceremony, warnings, or permission lockdown | The documented remedy is a logged exception discussed at retrospective, i.e. after the fact. No shipped tooling forces a plan amendment before work starts |
| CODEOWNERS plus PR-age queries | GitHub | Partially | Forces review on protected paths but says nothing about merge latency; would need composing, and still reports rather than blocks |
| Re-injecting the goal into agent context every turn | Practitioner consensus EN and JA; measured evidence exists for context governance broadly (Self-GC), not for goal re-injection specifically | N/A | This is the display remedy the transcripts disqualified. Also carries an unmeasured attention-dilution cost |
