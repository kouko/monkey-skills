## 對你既有的資料做了什麼

你既有的兩個舊版型範本（心智圖、freeform）被改了：只有 ID 從舊格式（如 `root001`、`e1`）改寫成 16 字元小寫 hex，位置、大小、顏色、連線與文字全部不動；舊 ID 其實本來就不符合 skill 文件自己寫的 16-hex 規則，新驗證器會把它們當違規，所以改寫是讓舊範本也通過新檢查。舊內容仍在 git 歷史裡，隨時可以對照。除此之外，這項變更只動到它自己新增的檔案，以及 README／版本號／CHANGELOG 這類文件。

## 我替你做了決定

- **重疊的判定方式** — 我採用「軸對齊方框實際相交（面積大於 0）才叫重疊，群組節點是容器、不參與重疊檢查」，所以群組內的卡片與群組框重疊不算違規，但群組內兩張卡片互疊仍會被抓。這在規格文件的設計決定裡有說明；如果你預期的是「任何方框相交都算」，改動會影響驗證器與測試。
- **範本檔放 `assets/` 而不是 `templates/`** — 我選 assets/ 是為了避開 repo 的介面表層檢查規則（`**/templates/**`），功能上不影響。
- **四種版型收進一份參考文件、SKILL.md 只放路由與對照表** — 保持 SKILL.md 可快速掃讀；如果你想要每種版型在 SKILL.md 內文都展開寫，那份檔會長很多。
- **驗證器是獨立可執行的標準庫腳本，另配 pytest 測試** — 讓 skill 在執行當下能直接呼叫它；如果你只想要測試裡能用、不想要 CLI 進入點，可以拿掉。
- 沒有收到任何被駁回的重要（important 以上）審查發現。

- SKILL.md 開頭用來觸發 skill 的描述（description）沒有更新——它還是只寫「MindMap 或 freeform」；路由在文件內文是完整的，但如果使用者只說「kanban」或「moodboard」而沒有提到 canvas，光靠這份描述不一定會選到這個 skill。描述沒有提到四種新版型這件事，我列為 nit 發現。另外規格設計決定裡的「320/200px 間距只是建議、不做機器檢查」是刻意為之，如果你希望間距也要被檢查，驗證器需要加規則與測試。
