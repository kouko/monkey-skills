## 我幫你決定的地方

- **調高規則文字裡某個字數上限之前，先想辦法在檔案裡騰出空間**——有兩個任務都遇到「這份文件字數快滿了」，選的做法是先在檔案裡找地方壓縮或搬去別的參考檔案，不夠才調高上限。這是呼應這次改動自己要求的「調高上限要有代價」，選了比較保守的一邊，結果是這次改動全程沒調高任何上限。如果之後想放寬，代價是要回頭把「先縮減再調高」這句判斷改掉。
- **兩個子專案的測試不能塞進同一次執行,選擇多寫一個十幾行的小工具腳本,而不是放寬測試涵蓋範圍**——遇到「同時測兩個子專案時,其中一邊會用錯的匯入規則導致另一邊測不到」的技術限制，選擇補一支小腳本讓兩邊各自跑一次、再把結果合起來看，而不是犧牲涵蓋範圍去換方便。換句話說是「多一點膠水程式碼」換「不縮小測試範圍」。如果之後想改回一次執行到底，要先確認兩個子專案的測試設定能不能合併。
- **同一次審查卡到第三輪要留的那行結論，訂成「下一個人事後會查」而不是「沒寫就不能往下走」**——因為這個專案的原則明講不能只靠文字當關卡、真正要擋的東西一定要寫進自動判定，而這次改動的範圍又講明不新增自動判定，兩邊放在一起，只能選「事後有人查」。如果之後真的想讓它變成擋人的關卡，要回頭補一支自動判定，不能只改文字。
- **版本號調高一級（不是最小的一級）**——因為這次改動讓兩道審查各多一個判斷項目、紀錄格式多一個欄位，雖然沒有任何舊規則的行為被改變，但影響範圍算「新增能力」不是「修一個錯字」，所以選了比最小更高一級的版本號。
- **這次改動自己的第 5 筆派工紀錄，把一支舊測試裡寫死的數字比下去，變成新的紅燈**——這不是我幫你決定的事，而是這次改動走到分支收尾這一步時，自然而然踩出來的落差；我沒有去修它（照規則，我只負責記錄），留在下一節給你看。
- **目前的審查紀錄裡，沒有出現「審查者提了問題、最後被人用『這樣就好』擋下來」的例子**——六筆第一輪的問題全部後來被確認修好，沒有一筆是被否決掉、不修了事的，所以這裡沒有東西要特別攤開給你看。
- **把某一筆整合 commit 的說明文字重寫過**——負責把 W1-05 那個任務的成果併回主線的那一筆 commit，原本漏了「這是哪個任務做的」這一行標記；漏掉的原因是它併的那份檔案（規則登記檔）合併出來的結果，跟合併前的兩邊都不一樣，系統的規則要求這種情況一定要補這行標記。我選擇把那一筆 commit 的說明文字改寫、把標記補上，而不是另外開一筆新的 commit 去補。後果是：**這一筆改寫之後，它原本的版本代號、以及在它之後才做出來的每一筆版本代號，全部換成新的**——舊代號從此在這個分支上查不到了；審查紀錄檔裡原本記著舊代號的每一處都已經跟著換成新代號，兩邊現在對得上。因為這個分支到目前為止都還沒推上去給任何人，沒有人手上還握著舊代號，所以這個「換代號」的動作沒有波及任何人。
