# 精簡 Loom 五階段流程
originator: kouko
kind: product
needs-design: yes — 審查時機、使用者提問與多階段證據狀態會改變，現有規格未涵蓋這次精簡
status: confirmed 2026-09-06

## Problem
Loom 的主流程實際上已經是 Start、Plan、Build、Review、Ship，但每個階段內仍維護速度模式、波次審查與多份重複證據。小型變更因此反覆派工、審查、記錄與重跑，使用者等待很久，卻沒有得到相稱的品質提升。

## Proposed outcome
保留現有入口與五階段主流程，把驗證強度改為系統依風險自動決定。一般變更只在分支結束做一次主審查；高風險邊界仍可提前檢查，但最後不重審沒有改變的內容。刪除使用者可選的速度模式、波次門檻和同一事實的重複載體。

## Acceptance
1. 一個一般變更在完成任務時只執行必要測試，不觸發正式審查，並在分支結束完成一次主審查後才可出貨。
2. Loom 會依變更風險自動選擇機械檢查、一般審閱或高風險加強驗證，使用者不再選擇或記錄速度模式，也不能降低必要驗證。
3. 安全、權限、遷移、公開介面、Skill、契約或檢查器等高風險變更可以提前檢查；分支結束時只補尚未覆蓋或其後改變的範圍。
4. 審查完成後只要內容改變，舊證據便會失效並阻擋出貨；內容未改變時，Ship 不會重新派出完整審查。
5. 新流程不再要求波次審查、速度模式狀態、review-only 提交、人工派工狀態或重複的盲跑報告，但仍保留必要測試、獨立審閱、未解決問題阻擋與對抗驗證。
6. 用一個普通變更與一個高風險變更實跑後，兩者都能完成驗收；相較現行流程，審查派工、重複測試與流程提交數明顯下降。

## Constraints
- 保留 `capture-intent`、`write-spec`、`write-plan`、`build`、`review`、`ship`、`maintain` 的既有入口名稱；只重新劃分責任。
- 維持三個 Loom plugin，且 loom-code 仍可獨立安裝。
- 保留測試先行、審閱者與實作者分離、內容指紋、未解決發現阻擋，以及高風險變更的加強驗證。
- 現有進行中分支不強制遷移；它們可使用啟動時已載入的舊流程完成。
- 採硬切換，不在新版本同時維護新舊格式。
- 不修改既有未追蹤的 `work/` 內容。

## Value case
GO。現行主要成本來自重複審查、派工、證據與測試，而不是五個階段本身；刪除這些重複機制能直接縮短小型變更的等待時間，同時保留高風險工作的品質保護。

## Out of scope
- 重新命名或合併現有 Skill 入口。
- 降低安全、權限、資料遷移、公開介面或檢查器變更所需的驗證強度。
- 強制遷移、改寫或清理目前其他 worktree。
- 建立另一套 production-grade runner 或長期效能基礎設施。
