# 地圖歷史讀取會靜默漏掉檔名含非英文字元的票
originator: kouko
kind: engineering
needs-design: no — 只改一支腳本讀 git 檔案清單的方式與它的測試；命令列參數、輸出格式、exit code 都不動；沒有使用者讀或輸入的介面改變
evidence: [loom-workflow/skills/decision-map/scripts/check_map_fog.py, loom-workflow/skills/decision-map/scripts/test_check_map_fog.py]
status: open

## Problem
decision-map 在檢查「霧」有沒有被違規重用時，要去比對主幹上那一版的票（ticket）有哪些已經從霧畢業。讀取那份歷史時，腳本先用 git 列出主幹版本的票檔清單，再逐一取內容。

腳本用 `git ls-tree -r --name-only <base>` 取那份清單。git 預設的 `core.quotepath` 會把含非 ASCII 字元的路徑（例如日文、中文命名的票）整個用雙引號包起來、並把非 ASCII 位元組轉成跳脫序列。腳本接著用 `name.endswith('.md')` 篩檔（`check_map_fog.py` 的列檔與篩檔兩處）——被引號包住的路徑結尾是引號而不是 `.md`，於是這張票**被靜默跳過**：不報錯、不警告，只是它的畢業關係從結果裡消失。後果是檢查可能放行一個其實違規的霧重用，或反過來誤判，而使用者看不到任何線索。

這是既有行為，不是任何一次改動造成的。它是在一次**後來被放棄、從未合併**的效能改動中被對抗者發現的：那次改動重寫了這段讀取邏輯，但因為約束是「行為一個位元組都不能變」而原封保留這個毛病，並當場決定另開一次改動來修——就是這一份。那次的探針隨著分支一起放棄了，所以**這個 repo 裡目前沒有任何測試釘住這個行為**；修的時候是新增回歸測試，不是去改既有探針。

## Proposed outcome
1. 讀主幹版本的票檔清單時改用「不會加引號」的取法（git 有以空位元組分隔的輸出模式），或在比對副檔名之前先把 git 的引號與跳脫還原。
2. 檔名含非 ASCII 字元的票，跟純英文檔名的票一樣被讀到、一樣參與畢業關係的比對。
3. 解析不了的票仍然整體報錯（維持既有語意），不因為這次修改而變成靜默跳過；沒有票目錄仍然是回傳空結果、不報錯。
4. 既有測試不動；新增回歸測試涵蓋含日文、中文檔名的票（目前沒有任何測試釘住這個行為，所以是新增而不是修改）。

## Acceptance
1. 沙盒裡造一份地圖，主幹版本有三張票：一張純英文檔名、一張日文檔名、一張中文檔名，三張都帶畢業標記；讀取主幹歷史時三張都被算進去（改動前只有第一張）。
2. 同樣的沙盒裡，票的檔名含空白、含 `#`、含表情符號各一張，也都被算進去。
3. 兩種既有行為原樣保留：主幹版本沒有票目錄時回傳空結果、不報錯；某張票內容解析失敗時整體報錯，訊息與 exit code 跟改動前逐字相同。
4. `loom-workflow/skills/decision-map/scripts/` 的既有測試一字不動、全綠；**新增的回歸測試**（日文與中文檔名各一張票，讀 base ref 歷史時都被算進去）在乾淨環境裡跑得起來且會通過——這條是新增的，不是改既有探針，因為目前沒有任何測試釘住這個行為；整包測試綠。
5. loom-workflow 版本 bump、CHANGELOG 寫明修了什麼。

## Constraints
- 只改讀清單這一段，不改批次讀內容的解碼方式（那部分剛修過，有 CJK 與 CRLF 的回歸測試守著）。
- 「某張票讀不到就整體報錯」的語意不可放寬。

## Out of scope
- decision-map 其他讀 git 的路徑。
- 票檔名的命名規則本身（不禁止非 ASCII 檔名，就是要讓它能用）。
