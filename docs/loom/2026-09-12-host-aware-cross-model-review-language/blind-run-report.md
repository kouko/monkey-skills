# 依執行環境選擇跨模型審查工具 — 我試了什麼、結果如何

於 2026-09-12，在乾淨的專案副本、版本 `73c6b3d` 上試驗。

## 你逐條要求的行為

### 1. 在 Codex 執行時，不把 Codex 自己當成獨立審查者
- **如何試**：檢視候選工具的探測順序與排除規則，並執行聚焦契約測試。
- **結果**：Codex 只會依序探測 Claude Code、Gemini；目前執行環境明確被排除。
- **證據**：「依執行環境選擇工具並具備完整退路」測試通過。
- **判定**：可用。

### 2. 在 Claude Code 執行時，不把 Claude Code 自己當成獨立審查者
- **如何試**：檢視 Claude Code 路徑及兩套獨立文字契約。
- **結果**：Claude Code 只會依序探測 Codex、Gemini；不會推薦自己。
- **證據**：「兩套契約的模式保持一致」測試通過。
- **判定**：可用。

### 3. 使用「由另一個模型家族進行獨立審查」的直接說法
- **如何試**：搜尋實際會顯示給使用者的文字，並執行禁用舊稱呼的測試。
- **結果**：顯示內容採用不同模型家族獨立審查的語意；舊稱呼未留在執行文字中。
- **證據**：「排除目前環境並處理無工具情況」測試通過，唯讀搜尋也未找到舊稱呼。
- **判定**：可用。

### 4. 保留每次詢問、非阻塞提示及固定工具三種既有行為
- **如何試**：分別檢查三種模式，並執行工具選擇的聚焦回歸測試。
- **結果**：每次詢問仍會等待回答；提示仍繼續工作；固定工具失效時不會暗中替換。沒有可用工具時不顯示無效選項。
- **證據**：工具選擇測試 22 項全數通過。
- **判定**：可用。

### 5. 非阻塞提示使用前後各兩個空白行的單欄表格
- **如何試**：直接檢查原始 Markdown 範例的換行、欄數、標題列及內容列。
- **結果**：原始內容是兩個空白行、單一標題、分隔列、單一描述格、兩個空白行；沒有第二欄或裝飾列。
- **證據**：「單格 Markdown 表格並保留間距」測試通過，差異空白檢查也通過。
- **判定**：可用。

### 6. 優先使用目前環境的原生問答介面，預設建議不啟用外部審查
- **如何試**：檢查兩種環境的原生能力條件、選項語意、在地化規則及所有退路。
- **結果**：有原生介面時，兩個選項會以目前對話語言顯示，並在介面要求推薦時推薦「這次不使用」。沒有原生介面時改用等待回答的純文字問題；沒有跨模型工具時說明不可用並繼續。
- **證據**：「完整原生能力規則」與「依執行環境選擇工具並具備完整退路」測試通過。
- **判定**：部分可用——文字契約與聚焦測試已驗證；未在 Codex 與 Claude Code 的真實互動介面逐一點選。

兩組顯示文字的聚焦測試分別為 16 項與 23 項，全部通過。本報告不主張完整套件或對抗探針的結果；它們由最後驗證各執行一次。
