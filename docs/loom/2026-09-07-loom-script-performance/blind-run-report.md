## 我替你決定的事

- **第 5 條的目標數字被下修**——原本設想「驗證跟更新這兩個動作,票只被讀一次」,但實際量到「更新」動作因為內部還會再呼叫一次「驗證」,做不到只讀一次,只能做到「讀兩次再加一次」而不是原本更沒效率的「讀四次再加一次」。這個下修是在動手實作之前就先跟你對過並寫進計畫,不是事後補救;如果你原本期待的是真正只讀一次,現在的結果離那個更遠一步的優化還有距離。
- **第 4 條保留了一個原本就存在的小毛病**——如果一張票的「檔名」本身含有非英文字元（例如日文),從歷史紀錄讀取時會被悄悄跳過、不會出現在結果裡。你要求這次改動「看得見的行為一個位元組都不能變」,所以這個毛病被刻意原封不動地留著,會另外排一次改動去修。如果你的地圖裡剛好有這種檔名的票,你會發現它們在讀歷史時被漏掉——這不是這次改動造成的,是本來就有的。
- **第 2 條沒有做到你原定的「0.4 秒以下」的目標,但沒有被砍掉重做,而是實測數字誠實回報**——依照你的規則「做不到就整段退回不做」,但因為輸出零改變這個核心要求完全達成、只是速度提升的具體門檻沒摸到,審查那邊的紀錄是保留這個改動並如實記錄數字,不算違反你的安全網規則,但你應該知道門檻沒達到。
- 目前為止沒有任何「重要或更嚴重」等級的問題被看過又刻意放行不修——沒有這類項目需要跟你交代。

## 你可能還沒想清楚要不要的事

- 第 2 條的秒數是在一台當下負載偏重的機器上量的,兩邊倍率關係看起來穩定,但如果你在意的是絕對秒數要壓在 0.4 秒以下,可能需要在一台空閒的機器上重新量一次才能下定論。
