## 我幫你決定的事
- 三個檢查程式的任務排順序做,不平行——因為它們改同一個 3,800 行的檔案,平行只會換來衝突,不會換來速度。
- 這次改動自己合流時要走舊的關閉方式(不是甲案)——因為系統上裝的檢查程式版本還沒換,新規則對這次改動自己的推送不生效。
- 「提意見的讀者才算開著的 finding」以「還沒被標記為已解決或已駁回」為準,駁回(dismissed)的意見算已結案。
- 判定用路徑完全相同來認定「有沒有碰到意見指名的檔案」,不用前綴模糊比對——避免安全門檻被放寬。
- 「內容相同」的比對方式用 git 的樹狀雜湊,先比對 commit 代號完全一樣的捷徑,代號不同才去比內容,盡量少花算力。
- 舊的「另開關閉 commit、多一輪」寫法保留繼續能用,不是被新寫法取代——舊分支不會因此壞掉。
- 「站文字改寫、版本號 1.4.0、記憶步驟」這件工作已經另外在平行的一條分支上開工,跟我這次驗的內容是分開跑的。

沒有被駁回的重大意見需要在這裡列——這次審查紀錄裡我看到的都是通過。
