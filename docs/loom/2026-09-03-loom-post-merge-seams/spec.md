## Requirements
REQ-1 — Intent close commit passes the push gate
  On a branch whose parent commit is already on the trunk, a commit whose message is `docs(loom): close intent <change-id>` (the ship station's step 6 wording) and whose only change is that intent's `status:` line moving from `confirmed <date>` to `closed <YYYY-MM-DD> — PR #<N>` passes `python3 <loom-code>/scripts/loom_checker.py push` — provided the checker can recompute from the parent's tree that the change really merged (its review.json is there with a passing branch-end round) — and `loom_checker.py intake write-plan <change-id>` on that intent blocks with `intake.confirmed: … this change is closed (PR #<N>); a new change starts from a new intent` → Acceptance #1
REQ-2 — Contract grammar knows `closed`, and closed is terminal
  `loom-code/contract/manifest.yaml` (`status` grammar) and `loom-code/contract/templates/intent.md` (status comment) both list `closed <YYYY-MM-DD> — PR #<N>`; `--list-rules` describes it under `intake.confirmed`; `test_the_repos_own_change_matches_its_own_review_json` derives `{intake.confirmed}` as the expected block when the repo's own intent is closed; the declared package command `python3 -m pytest loom-code/scripts/ scripts/ .claude/hooks/ -q` passes locally and in the CI job `pytest + knowledge-drift + codex-manifest-drift` (.github/workflows/loom-code-ci.yml) → Acceptance #2
REQ-3 — Scaffold copy is host plumbing for the trailer rule too, by content
  `push.dispatch-covers-tasks` ignores a path in the host-plumbing set (`HOST_PLUMBING_FILES`, `HOST_PLUMBING_DIR_PREFIX`) only when that path's blob at the commit equals the canonical file the running checker ships (see Design decision); a commit that only refreshes `.codex/hooks/` with genuine scaffold output carries no trailer duty, while any other content under those paths counts as gate work and still needs a trailer → Acceptance #3
REQ-4 — Checkpoint cost measured on this change
  `docs/loom/2026-09-03-loom-post-merge-seams/evidence/checkpoint-cost.md` holds one table — per checkpoint: commits, dispatches, review rounds — plus the branch's `git rev-list --count <trunk>..HEAD`, side by side with the #771 replay (34 commits / 31 today), and one line of recommendation; no coefficient is changed → Acceptance #4
REQ-5 — Plugins versioned and observable

## Design decision
- **Intent-close shape for `push.review-only-head` (agent-decided; the one rule whose semantics change — intent Constraints, as amended by the user 2026-09-03).** The rule keeps its existing shape (HEAD touches only `docs/loom/<change-id>/review.json`) and gains exactly one more accepted shape, recognised entirely from git and the parent's tree, in this order — the first failing test sends the push down the ordinary path, which then blocks as today:
  1. `git diff-tree --no-renames -r HEAD^ HEAD` lists exactly one entry: status `M`, unchanged mode, path `docs/loom/intent/<change-id>.md` (a regular file, no rename/type change).
  2. The unified diff of that file has exactly one removed line and one added line (context lines aside); both begin with `status:`; the file has exactly one `status:` frontmatter line before and after; no other byte differs (a trailing-newline change or CRLF change is another difference).
  3. The removed value matches `confirmed <date>`; the added value matches `closed <YYYY-MM-DD> — PR #<N>` with the date accepted by the same `is_real_date()` the `confirmed` grammar uses and `<N>` a positive integer. Only this transition is accepted: `closed → confirmed`, `withdrawn → closed`, `open → closed` are ordinary pushes and block. `closed` is therefore terminal for the gate.
  4. `HEAD^` is an ancestor of the trunk ref (`git merge-base --is-ancestor HEAD^ <trunk>`; trunk resolved as the checker already does).
  5. In `HEAD^`'s tree, `docs/loom/<change-id>/review.json` and `docs/loom/<change-id>/blind-run-report.md` exist, and the record rules are recomputed against that review.json as it stands there: `push.review-schema`, `push.verdicts-ge-2` on its latest round, whose `scope` must be `branch-end` (or the wave-end round the station recorded as branch-end) with every verdict PASS or PASS_WITH_NOTES, `push.reviewer-ne-implementer`, `push.dismissed-by-reviewer`, `push.open-findings-closed`, `push.second-vendor-honoured`. These artifacts reach the trunk only through a merge, so this is the recomputed proof that the change merged; the PR number in the status line is a pointer for humans, not evidence, and the checker does not consult the network.
  6. When all five hold, the delta rules that concern the change's own diff — `push.reviewed-sha`, `push.probes-package-tests`, `push.probes-adversarial`, `push.dispatch-covers-tasks`, `push.frozen-store-untouched` — are not applicable (the delta is one status line and the change's diff is already on the trunk) and the checker prints one line `push.review-only-head: intent-close commit for <change-id> — delta rules not applicable` so the skip is visible in the output, never silent.
  Reason: the ship station already prescribes this commit; this is the narrowest shape that lets it through, every element is recomputed from git, and nothing declared by the agent (message, trailer, flag) is trusted. Rejected: folding `closed` into the next change's review-only commit (weeks of an intent that looks unfinished, the ship station's own warning); a waiver or flag (no waivers — concept-model §7, PRINCIPLES non-negotiable 3).
- **`intake.confirmed` on a closed intent (agent-decided).** Blocks with the message above; `closed` is not a pass state anywhere. The status grammar is one regex in `loom_checker.py` shared by `intake.confirmed`, `intent.schema` and the new shape, so the three cannot drift.
- **Content-bound plumbing exemption (agent-decided, replaces the path-prefix reading of round 1).** `check_dispatch_covers_tasks` filters `commit_paths()` through `_is_host_plumbing()` (loom_checker.py:400) **and** a blob comparison: `.codex/hooks/loom_checker.py` and `.codex/hooks/git_exec.py` must equal the running checker's own source files (`Path(__file__).parent`), the copy's stamp line (`# loom-checker <version>`) stripped; `.codex/hooks/loom-checker` must equal the shim the scaffold renders for the running version; `.codex/hooks/contract/<rel>` must equal the `contract/<rel>` shipped next to the running checker; `.codex/hooks/.loom-hook-fired` is ignored (it is git-ignored anyway). A path that fails the comparison is classified by the manifest as today (`gate`) and owes a trailer. On Codex the running checker is the copy, so the comparison of the checker file is trivially true — that is the artifact-content gap concept-model §7 already accepts, recorded here rather than hidden.
- **Test oracle for the self-check (agent-decided).** `test_the_repos_own_change_matches_its_own_review_json` (loom-code/scripts/test_loom_checker_intake.py:385-447) derives its expected block set dynamically; it gains the branch: intent status `closed …` → expected `{intake.confirmed}`. The CI failure it currently produces is kept as `evidence/ci-781-intake-confirmed.md`.
- **Contract version (agent-decided).** Stays 1.0: an added accepted value is backward compatible for every consumer requiring `>=1.0`. Plugin bumps as REQ-5.
- **Checkpoint-cost table (agent-decided).** Written by the blind-runner at branch end from `git log` and `review.json`, so the numbers are recomputed by someone who did not produce them. Recommendation only — the decision is deferred to the second and third real change (user-decided 2026-09-03).
- **Merge (user-decided 2026-09-03).** The user presses merge; the agent stops after `gh pr create`.
- **Test nits (agent-decided).** Fixed in the task that already touches each file (`test_check_mechanisms.py`: R28-O2, R30-O1, R30-O2; `test_session_start_words.py`: R30-O3; `loom_checker.py`: R24-O2); R30-O2's guard asserts, via `inspect.getsource(check_mechanisms)`, that no `subprocess` call in the module names `wc`.

## Alternatives considered
- A `push` flag or waiver for docs-only commits — rejected: a declared bypass; the design has no waivers.
- Verifying the PR number against GitHub — rejected: the checker never consults the network (it must give the same answer offline and on Codex); the merged record on the trunk is the proof.
- Writing `closed` before the merge, inside the last review-only commit — rejected: false until the merge, and that commit may touch only review.json.
- Exempting plumbing paths by prefix for the trailer rule (round-1 design) — rejected by the red team: it lets gate content hide under `.codex/hooks/contract/`.
- Bumping only loom-code — rejected: Acceptance #5 (user-confirmed) and both sibling plugins describe the status values in prose.
