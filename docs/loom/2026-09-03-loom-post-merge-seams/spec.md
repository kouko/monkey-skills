## Requirements
REQ-1 — Intent closed on the branch before the merge, under the unchanged push gate
  The ship station's order becomes: push → `gh pr create` (the PR number is now known) → commit `docs(loom): close intent <change-id>` changing that intent's `status:` line from `confirmed <date>` to `closed <YYYY-MM-DD> — PR #<N>` → a review-only commit (only `review.json`; `reviewed_sha` = the close commit; package-tests and adversarial probes re-pinned at it) → push again. `loom_checker.py push` passes on its existing rules, no rule gains a shape and nothing is bypassed; `closed` reaches the trunk only by the merge. `loom_checker.py intake write-plan <change-id>` on a closed intent blocks with `intake.confirmed: … this change is closed (PR #<N>); a new change starts from a new intent`. The already-merged intent `2026-09-02-simple-loom-flow` is closed the same way inside this change's own diff. Two residuals are stated, not hidden: the close commit's own contents are not machine-checked beyond trailer duty (a docs-typed file smuggled into it is caught only by the user reading the PR diff before pressing merge — the user is the merge gate by their own decision), and CI does not run `loom_checker.py push` (the push gate is client-side; CI recomputes the intake/standing/contract rules, the mechanism population and the package tests) → Acceptance #1
REQ-2 — Contract grammar knows `closed`, and closed is terminal
  `loom-code/contract/manifest.yaml` (`status` grammar) and `loom-code/contract/templates/intent.md` (status comment) both list `closed <YYYY-MM-DD> — PR #<N>`; the date must pass the same `is_real_date()` the `confirmed` branch uses (a real calendar date; the checker does not compare it to today's clock) and `<N>` is a positive integer; `--list-rules` describes it under `intake.confirmed`; **terminal**: `intake.confirmed` also blocks when the intent file's history on the current branch (`git log --format=%H -S'status: closed' -- <intent path>`, non-empty) shows a `closed` status while the current status is anything else, with the message `intake.confirmed: <change-id> was closed (PR #<N>) and closed intents are not reopened; start a new intent` — a reopen therefore cannot enter write-plan or write-spec on any branch that carries the closed history, and a branch that deletes the history is a different file with no `closed` ever recorded, which the trunk still has; `test_the_repos_own_change_matches_its_own_review_json` derives `{intake.confirmed}` as the expected block when the repo's own intent is closed; the declared package command `python3 -m pytest loom-code/scripts/ scripts/ .claude/hooks/ -q` passes locally, and the CI job `pytest + knowledge-drift + codex-manifest-drift` (.github/workflows/loom-code-ci.yml:114, same paths with `-v`; only the exit code must agree) passes → Acceptance #2
REQ-3 — Scaffold copy is host plumbing for the trailer rule too, by content, where a canonical exists
  `push.dispatch-covers-tasks` ignores a path in the host-plumbing set (`HOST_PLUMBING_FILES`, `HOST_PLUMBING_DIR_PREFIX`) only when an external canonical exists — the checker doing the push is not itself the `.codex/hooks/` copy (Claude Code: the plugin checkout; any host: a repo that carries `loom-code/contract/` and `loom-code/scripts/`, i.e. this repo) — **and** the path's blob at the commit equals that canonical file (see Design decision). A commit that only refreshes `.codex/hooks/` with genuine scaffold output then carries no trailer duty; an altered, added, deleted or mode-changed entry under those paths counts as gate work and needs a trailer. When the checker doing the push is the copy (Codex in an adopting repo) there is no canonical to compare against and no exemption applies — every plumbing edit keeps trailer duty, exactly as today → Acceptance #3
REQ-4 — Checkpoint cost measured on this change
  `docs/loom/2026-09-03-loom-post-merge-seams/evidence/checkpoint-cost.md` holds one table — per checkpoint: commits, dispatches, review rounds — plus the branch's `git rev-list --count <trunk>..HEAD`, side by side with the #771 replay (34 commits / 31 today), and one line of recommendation; no coefficient is changed → Acceptance #4

## Design decision
- **Close before the merge (user-decided 2026-09-03; replaces round 1's new push shape).** The intent is closed on the change branch once the PR number exists; the review-only commit that follows re-pins `reviewed_sha` and the probes at the close commit, exactly as any post-review docs edit is handled today. Consequences: no push rule changes (the intent Constraint stands as written); the closed line lands on the trunk with the squash and nowhere else, so a `closed` on the trunk is itself the proof of the merge — no PR-number verification is needed and none is done; a PR that is never merged leaves `closed` on a dead branch only. The ship station text (`loom-code/skills/ship/SKILL.md` §6) is rewritten to this order, and its "the status line cannot be written on the branch" paragraph goes. Rejected: the round-1 design (a second accepted HEAD shape for `push.review-only-head`) — one more rule semantics, a grammar-only proof, and every red-team escape listed in evidence/spec-redteam-r1.md.
- **`intake.confirmed` on a closed intent (agent-decided).** Blocks with the message above; `closed` is not a pass state anywhere. The status grammar is one regex in `loom_checker.py` shared by `intake.confirmed` and `intent.schema`, so the two cannot drift; the closed date goes through `is_real_date()` in the same branch as `confirmed`. The reopen check reads the intent file's git history on the branch (REQ-2) — a recompute, not a flag.
- **Content-bound plumbing exemption, only with an external canonical (agent-decided; round 2 spec-C6/R7).** `check_dispatch_covers_tasks` filters `commit_paths()` through `_is_host_plumbing()` (loom_checker.py:400) **and** a blob comparison against a canonical the running checker can name without trusting the repo: the checker doing the push is identified by `Path(__file__).resolve()` — if that path lies under the repo's `.codex/hooks/`, the checker is the copy, no canonical exists, and the exemption is off (the Codex case; the artifact-content gap of concept-model §7 is not widened by this change). Otherwise the canonical is the source tree the checker runs from: `.codex/hooks/loom_checker.py` and `git_exec.py` must equal `<that dir>/loom_checker.py` / `git_exec.py` with the copy's stamp line (`# loom-checker <version>`) stripped; `.codex/hooks/loom-checker` must equal the shim `codex_scaffold.SHIM_TEMPLATE` renders for that version; `.codex/hooks/contract/<rel>` must equal `<that dir>/../contract/<rel>`; `.loom-hook-fired` is ignored. "Two cached plugin versions" is not ambiguous: the canonical is whichever checkout the hook invoked (the hooks.json of the version Claude Code loaded), and a copy stamped with another version simply fails the comparison and owes a trailer. A plumbing path with no canonical counterpart (an extra file under `contract/`) fails the comparison. Recorded limitation: on Codex the scaffold refresh commit (and the first-contact scaffold commit of `write-plan` step 0b) still needs a `Task:` trailer, which is a seam of its own — it goes to a follow-up intent, not this change.
- **Test oracle for the self-check (agent-decided).** `test_the_repos_own_change_matches_its_own_review_json` (loom-code/scripts/test_loom_checker_intake.py:385-447) derives its expected block set dynamically; it gains the branch: intent status `closed …` → expected `{intake.confirmed}`. The CI failure it currently produces is kept as `evidence/ci-781-intake-confirmed.md`.
- **Contract version (agent-decided).** Stays 1.0: an added accepted value is backward compatible for every consumer requiring `>=1.0`. Plugin bumps as REQ-5.
- **Checkpoint-cost table (agent-decided).** Written by the blind-runner at branch end from `git log` and `review.json`, so the numbers are recomputed by someone who did not produce them. Recommendation only — the decision is deferred to the second and third real change (user-decided 2026-09-03).
- **Merge (user-decided 2026-09-03).** The user presses merge; the agent stops after `gh pr create`.
- **Test nits (agent-decided).** Fixed in the task that already touches each file (`test_check_mechanisms.py`: R28-O2, R30-O1, R30-O2; `test_session_start_words.py`: R30-O3; `loom_checker.py`: R24-O2); R30-O2's guard asserts, via `inspect.getsource(check_mechanisms)`, that no `subprocess` call in the module names `wc`.

## Alternatives considered
- A `push` flag or waiver for docs-only commits — rejected: a declared bypass; the design has no waivers.
- A second accepted HEAD shape for `push.review-only-head` with the merge proven from the parent tree (round-1 design) — rejected: one more rule semantics and a grammar-only PR pointer; superseded by closing on the branch.
- Writing `closed` inside the review-only commit itself — rejected: that commit may touch only review.json; the close is its own commit immediately before it.
- Exempting plumbing paths by prefix for the trailer rule (round-1 design) — rejected by the red team: it lets gate content hide under `.codex/hooks/contract/`.
- Bumping only loom-code — rejected: Acceptance #5 (user-confirmed) and both sibling plugins describe the status values in prose.
