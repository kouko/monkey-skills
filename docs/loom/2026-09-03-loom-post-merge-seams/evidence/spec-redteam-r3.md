## 2. New attacks on v4
2a. **Reopen via branch/rebase, not delete** — ESCAPES, important. `git switch -c x <trunk-sha-before-the-squash>` (or a local interactive rebase dropping the close commit) gives a branch whose `git log -S'status: closed' -- <path>` is genuinely empty — the close commit is simply not an ancestor. REQ-2's own defense only names "a branch that deletes the history is a different file... which the trunk still has" — that answers "is trunk's truth intact," not "can intake be entered locally on this branch." Fix: state the recompute's actual invariant — it blocks reopen only on branches descended from the post-merge trunk tip, and note this as an accepted, bounded gap (same shape as R9's push-gate residual) or add a check that `branch_base` includes the close commit.
2b. Delete+re-add the status line — HOLDS. `-S` fires on the delete commit itself (occurrence count 1→0), so rewriting doesn't dodge it on a branch that keeps that commit.
2c. **`-S'status: closed'` is a literal-byte match; the closed grammar may be whitespace-lenient** — ESCAPES, important. If the closed-branch regex accepts `\s+` (as `CONFIRMED` does today) a hand-edited `status:  closed …` (two spaces) parses as valid closed but never matches the hardcoded single-space literal pickaxe string — a later revert to `confirmed` then goes undetected. Fix: either pin the closed grammar to the exact literal spacing the pickaxe string uses, or derive the `-S` argument from the grammar regex's literal prefix rather than a second hand-typed string.
2d. New change-id file, same content — HOLDS, not an attack: the block message itself prescribes exactly this ("a new change starts from a new intent"); a fresh change-id is sanctioned behavior, not a dodge.
2e. **`Path(__file__)` symlink/copy outside `.codex/hooks/`** — ESCAPES, important but bounded. A Codex user who runs the checker from a copy/symlink placed elsewhere makes `Path(__file__).resolve()` fall outside `.codex/hooks/`, flipping the exemption on even on Codex — falsifying the design's unconditional "on Codex... no exemption applies." Given the user already controls that machine and the gate is client-side-only (REQ-1's residual), this adds no new privilege beyond what `--no-verify` or editing the checker source already grants — but the sentence should be scoped to "when invoked via the scaffolded hook path," not stated as an absolute.
2f. **Canonical comparison lets an attacker pick a weaker, superseded canonical** — ESCAPES, important. "the canonical is whichever checkout the hook invoked" (v4's own fix for R10) does not require the *latest* cached plugin version — with multiple caches on disk (this repo's own memory documents that as routine), an attacker can deliberately invoke an old cached checker whose bundled `contract/` differs from current, and craft a plumbing file that matches that stale canonical instead of the live one. Fix: pin canonical resolution to the version the *current session's hook actually loaded* (already true) but also state that a deliberately-stale local cache is an accepted risk of the same shape as 2e, not a new one — or require a version-freshness check.
2g. REQ-2 grammar: any string matching both `confirmed` and `closed`? — HOLDS. Both branches require a distinct literal keyword prefix (`confirmed`/`closed`); no string can start with both, so the alternation is structurally unambiguous.

**REQ-1 residual vs PRINCIPLES.md — FATAL.** REQ-1's residual reads: "a docs-typed file smuggled into it is caught only by the user reading the PR diff before pressing merge — the user is the merge gate by their own decision." This is not merely inconsistent with a sentence away from fixing — it contradicts two ratified lines directly: Non-negotiable #1 ("never a question that requires reading code") and Won't-do ("Ask the user to review specs, plans, or diffs for quality"). Pressing merge as a one-way-door choice is already sanctioned elsewhere (Design decision: "Merge (user-decided)"), but *justifying the smuggling gap by relying on the user reading the diff for quality* assigns exactly the role PRINCIPLES.md forbids. Fix: either add a machine check for the close commit's shape (the exactly-one-line diff round 1 proposed, now dropped) or rewrite the residual to not lean on user diff-reading as the catch — state it as an accepted, unmitigated gap instead (matching how R9's push-gate residual is honestly stated without invoking user review as the safety net).
