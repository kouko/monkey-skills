# Skill Consistency Check

[English](README.md) | **日本語** | [繁體中文](README.zh-TW.md)

> skill パッケージ内で互いに矛盾するルールを見つける — あるファイルが
> 要求することを別のファイルが禁止している、二つの上限値が食い違って
> いる、あるルールに従うと別のルールが禁じる手順を踏まざるを得ない、
> といった箇所。

ユーザーが明示的に invoke する **チェック用 skill**：skill フォルダを
指定すると、矛盾の一覧と全体の判定を返す。各矛盾には両側の
file:line、引用した原文、信頼度（high／medium／low）、一文の理由が
付く。

この README は GitHub で skill を読む人間向け。agent が実際に load
する operational ファイルは [`SKILL.md`](SKILL.md)。

---

## なぜこの skill があるのか

矛盾した指示があると、すべての行に従う agent はある状況でどう動いても
違反になる。書き手はこれに気づきにくい。両側が別ファイルにあったり、
言い回しが違ったり、特定の条件でしか衝突しなかったりするからだ。

以前の版はルールを論理式に変換して SMT ソルバーに渡していた。ブライン
ドテストでは埋め込んだ 27 件の矛盾のうち 7 件しか見つからず、精度は
約 18%。見逃しはほぼすべて変換の段階で起きていた。その後 10 ラウンド
のブラインド実験で、LLM が本文を直接読むほうがはるかに良いことが
分かり、ここで使う方法が決まった。

## 仕組み

```
skill folder ──► plan_groups.py ──► one group, or several groups
                                          │
             ┌────────────────────────────┴───────────────┐
             ▼                                            ▼
   read-through detectors                   walk-through detectors
   (read and report conflicts)              (act as the agent through
                                             3–5 situations)
             └────────────────────┬───────────────────────┘
                                  ▼
                           merge_report.py ──► verdict + report
```

- **二つの検出器**、それぞれ独立した subagent：通読（read-through）と
  実行シミュレーション（walk-through）。仕様は
  [`references/`](references/) にある。
- **グループ分け**：推定 30,000 tokens 以下のパッケージは丸ごと読む。
  それを超える場合は 1 グループ最大 25,000 tokens に分割する。各
  グループに SKILL.md、agents/ のファイル、SKILL.md が直接引用する
  ファイルを必ず入れ、残りのファイルは二つの方法で異なる分け方にする。
  一度も同じグループで読まれなかったファイルの組はレポートに列挙する。
- **判定**：high の発見が一つでもあれば「要修正」。medium と low は
  参考情報。
- **副作用**：なし。何もインストールせず、チェック対象のフォルダ内には
  何も書かない。レポートは別の実行ディレクトリに出力する。発見を自動
  修正することはない。
- **ホスト**：fan-out は「N 個の subagent を dispatch する」と抽象的に
  書いてあるので、同じ SKILL.md が Claude Code でも Codex でも動く。
  モデル名は固定していない。中位以上のモデルを使うこと（実験では最小
  クラスのモデルが 1〜3 件で止まった）。
- **徹底モード**（明示的に頼んだときのみ）：各方法を 2 回ずつ実行する。

---

## 限界

- 検証は Claude Sonnet（200k context）、約 25,000 tokens のパッケージ
  で行った。他のモデルは未検証で、レポートにもそう明記される。
- 条件付きの矛盾（共通の条件下でのみ衝突する）と、多段の推論が必要な
  矛盾は見逃すことがある。
- 正解キー付きの回帰テスト用コーパスは plugin の
  `tests/consistency-check-corpus/` フォルダにある。別のモデルに頼る
  前に、まずこれで確認すること。

---

## 使うとき

- 新しい skill、または大きく手を入れた skill を ship する前
- skill に従う agent の挙動がぶれていて、指示同士の食い違いが疑われる
  とき

## 使わないとき

- **設計品質の採点** — [`skill-judge`](../skill-judge/) を使う
- **実際のプロンプトでの挙動テスト** —
  [`dogfood-skill-testing`](../dogfood-skill-testing/) を使う
- **フォルダ構成や語数のルール** — repo の構造チェッカーが担当する
