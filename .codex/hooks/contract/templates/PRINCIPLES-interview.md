# 產品原則訪談（決策點①內執行，不另停）

開場（原樣說）：「做產品功能前這個 repo 要先有一份產品原則，我接著問你幾個問題來產生（約十分鐘），最後跟 intent 一起確認。」

問到清楚為止；每題白話，不出現機制名詞。
1. 這個產品是給誰用的？他們現在怎麼解決這件事？
2. 用起來最不能妥協的一件事是什麼（快、準、便宜、隱私、離線、好看）？排一下順序。
3. 有沒有明確「不做」的事？
4. 做壞了最糟的後果是什麼？誰會受傷？
5. 有沒有已經決定不能換的東西（平台、語言、付費服務、資料格式）？

產出 `PRINCIPLES.md`：
```
# Product principles
ratified-by: <name> <date>      # 使用者確認後 agent 寫
## Who
## Non-negotiables (ordered)
## Won't do
## Failure we must avoid
## Fixed choices
```
與 intent 一起覆述給使用者；使用者說「對」→ 寫 `ratified-by`。
