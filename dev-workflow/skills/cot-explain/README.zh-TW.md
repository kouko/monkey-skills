# CoT Explain

[English](README.md) | [日本語](README.ja.md) | **繁體中文**

> 指給它一份文件——或你剛結束的這段對話——它產出一份自包含的 HTML
> 說明頁，主體是一張 CoT（思路鏈）Mermaid 圖：每個節點是一個推理步驟，
> 每條箭頭都標著「為什麼這一步成立」。

---

## 這個 skill 做什麼

躺在長文件裡的推理、或只有你在場的那段對話，對其他人是不存在的。
這個 skill 把它變成看得見的東西。

它讀來源、抽出真正的推理鏈——有哪些主張、各自靠什麼支撐、兩兩之間怎麼
接上——然後渲染成一份 HTML：

1. 一句話結論
2. CoT Mermaid 主圖
3. 逐節點展開：主張 / 依據 / 這一步改變了什麼
4. 考慮過但被否決的選項 + 否決理由
5. 這條鏈依賴的前提，以及還沒有答案的問題

它是**一次性產出器**。不寫資料庫、不跨 session 追蹤。跑完就結束。

## 圖的格式慣例

用的不是通用 Mermaid，而是固定的 house style：

```
graph TB
subgraph r1["階段標題"]
direction LR
  A["<div style='text-align:left'>前提<br/>━━━━━━<br/>• 條列一<br/>• 條列二<br/>• 條列三</div>"]
  B[...]
  C[...]
end
A -->|塑造判斷基礎| B
B ==>|匯聚為| C
style A fill:#f8f9fa,stroke:#868e96,stroke-width:2px
```

- 每個節點：標題、一條 `━━━━━━` 分隔線、三到五條條列、靠左對齊
- **每一條**箭頭都帶標籤說明關聯——沒標籤的箭頭視為缺陷，不是省事
- 三種箭頭：`-->` 一般推導、`-.->` 背景或弱連結、`==>` 匯聚成結論的最後一步
- 節點顏色代表角色：前提、依據、阻礙、嘗試、轉折、結論

**版面是量出來的，而且這些數字可攜。**推理鏈又長又細，畫成扁平的
`graph LR` 在頁面上根本沒法看。規格的答案是外層 `graph TB`、每一列是一個
各自宣告 `direction LR` 的 `subgraph`、每列至多 3 個節點——**8 個節點切成
3/3/2 實測 773 × 824，接近正方 0.938**。

真正載重的是**列與列怎麼接**：**子圖對子圖（`r1 -->|…| r2`），絕不能節點
對節點**。只要列內任一節點指向列外，mermaid 就會丟掉這一列的 `direction`，
整組列塌成一條窄柱。每個數字都靠讀 SVG 裡的節點座標驗證過——單看 squareness
分不出「列真的排開了」和「框剛好比較寬」，有個被否決的候選分數還更高、列卻
是直排的——並且在 **mermaid 11.13.0（Obsidian 與 VS Code 預覽在跑的）與
11.17.0（現行）** 上算出逐位元相同的結果。

**字數限制是警告，不是失敗。**節點寬度由整張圖**最寬的那一條**決定，
所以閘只針對那一條提醒，而且永不阻擋。硬性字數上限會逼作者為了滿足一個
數字把句子弄殘，那比一個寬一點的框更糟。

這個版面刻意偏離 vault 自身的慣例（`graph LR`、不用 `subgraph`）——那些
檔案裝的是短鏈，13:1 咬不到它們。完整規格與量測表在
`references/mermaid-cot-spec.md`。

## 產出

**markdown 是產物，HTML 是衍生物。**`.md` 帶有與 vault 筆記標準對齊的
frontmatter，值得留下的頁面可以直接搬進 Obsidian。HTML 由
`render_cot_html.py` 機械轉換而來，用的是 markdown-it-py——本 repo 既有的
markdown 轉換器用的同一支函式庫——而且永不手改。

兩個檔都落在 `${TMPDIR:-/tmp}/cot-explain/`，**刻意是暫存的**：這類頁面多半
看過就算。要留就把 `.md` 搬進 vault，或把 HTML 發成 Artifact（claude.ai 上的
私有頁面，你可以再決定要不要分享）。發佈只問一次、絕不自作主張，因為那等於
把內容上傳。本地 HTML 從 CDN 載 `mermaid.js`，第一次開檔需要網路。

轉換器從一份「同類轉換器五天內靜默失敗五次」的 spec 借了三個性質：轉換失敗時
**大聲失敗且不寫任何檔案**、**檢查限定範圍**（mermaid 區塊與 code span 裡滿是
`|` 和 `**`，不該被誤殺）、以及**每張頁面都印上實際執行的那份複本的版本**。

## 忠實度——閘檢查不到的那一半

驗證腳本能證明頁面格式正確，**證明不了它有沒有忠實反映來源**，而且沒有任何機械方法做得到：每個節點形狀都對、每條邊都有標籤，讀者仍然可能帶走一個來源明確否決的結論。

這不是假設。對一份真實英文來源做 round-trip 測試的結果是：讀者會相信解法是「把呼叫**釘到特定路徑**」，但來源已經推導過固定路徑為何行不通、指定的是**自我定位規則**——照著做會實作出被否決的那個版本。判定原話：作為「為什麼」的敘述是忠實的，作為「要做什麼」的敘述是不可用的。

所以這個 skill 附帶 **Step 6 忠實度檢查**，在頁面交給不在場的人之前跑。它是 simulatability 式的 round-trip（forward simulation，Doshi-Velez & Kim 2017；Leakage-Adjusted Simulatability，Hase et al. 2020），分三輪：一個 agent 只讀頁面重建推理；第二個 agent 只看來源與那份重建、**不准看頁面**，判定哪裡被誤解、哪裡被漏掉；第三輪反向查，圖上有沒有來源根本沒有的東西。

**它不做什麼。**當來源是**要照著執行的文件**——寫來被行動、而不只是被閱讀的
東西——這頁講的是它為什麼這樣決定，**不能取代讀原件本身**。技術規格是最明顯的
一種；政策、合約、臨床流程、法規、編輯規範也完全適用同一條。這個界線是量出來的：對同一份密集的
工程 brief 跑了四輪，每一輪都把前一輪被點名的條款全部找回來，然後掉不同的、
沒人想過要找的實作細節——新缺陷 1 個、2 個、3 個。再加一個獵捕類別只是讓損失
換個地方，不會終止它。機制節點的逐字引用能縮小落差，**關不上**，
所以來源是要照著執行的文件時，頁面本身會這樣註明。

這頁真正該做的事在四輪裡都完好送達——被推翻的判斷、被否決的選項與理由、
附條件的撤退——而且最後三輪的幻覺檢查**什麼也沒抓到**。

由此得出的修法刻意做得很小。節點卡片只多一個欄位——`例外／失效條件`，即 Toulmin 的 *rebuttal*——因為「這個主張在什麼範圍內才成立」是摘要最常丟、丟了最傷的東西。圖的詞彙**完全沒動**。背後的規則是：**只加「用抄的」欄位，不加「要評的」欄位。**問「來源寫了什麼限制」，不同讀者答案一致；問「這個主張有多可信」，不會。

## 跟鄰近 skill 怎麼選

| 情境 | 用哪個 |
|---|---|
| 把已經存在的推理講給人聽，要一份可分享的頁面 | 這個 skill |
| 還在想，跨 session、要追蹤假設 | `think-orbit:thinking-session` |
| 過去推理依賴的假設破了 | `think-orbit:break-assumption` |
| 對話中途迷路，要在聊天室內重新定位 | `dev-workflow:recap-state` |
| 把 session 狀態交給未來的冷讀 AI | `dev-workflow:handoff` |
| 任何 Mermaid 圖型，不需要 CoT house style | `obsidian:obsidian-mermaid-visualizer` |

最關鍵的分界：**think-orbit 是拿來「想」的，這個是拿來「講已經想過的東西」
的。**兩者並存。

## 它會拒絕的事

- **不讀來源就畫圖**。抽推理鏈才是工作本身；從檔名推測出來的圖是虛構。
- **為了湊滿節點數而灌水**。真實推理步驟不到 5 步，它會直說並改建議寫散文。
- **編造被否決的選項**。來源沒考慮過替代方案，那一節就刪掉，不是填滿。
