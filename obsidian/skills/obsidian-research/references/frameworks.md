# Frameworks by layer (obsidian-research)

Frameworks listed by **how they are usually used** in a research note, not by what they "are": the same framework can serve two layers (SWOT can be one chapter's tool or a whole note's skeleton; a case study is both a choice and a sequence). Pick what makes this topic clearer; never force a framework onto a topic.

The layering follows practice in several fields — evidence-based medicine (pick a reporting guideline by study design → IMRaD → GRADE → CONSORT/PRISMA), Japanese QC (choose the QC Story type → its steps → QC tools → QC ways of thinking; JUSE names the last three the "three keys": https://www.juse.or.jp/upload/files/shanai_rensai_kaizen_01.pdf), systems engineering (life-cycle process → trade studies → technical reviews). No single source names all four layers; this list combines them.

## Layer 0 — Choose the note's structure

Match the question type, then take the skeleton (layer 1) and the tools to reach for inside chapters (layer 2).

| Question type | Skeleton (layer 1) | In-chapter tools (layer 2) |
|---|---|---|
| Explain a concept or technology | By topic dimensions (what it is → how it works → state of the art → limits → adoption) | 5W1H, issue tree |
| Compare options / choose a tool | Options → criteria → per-criterion chapters → matrix → recommendation | Decision matrix, Kano, JTBD |
| Decide / "should I…" | 空・雨・傘 (fact → meaning → action); open with SCQA | Decision matrix, bull / base / bear scenarios, pre-mortem |
| Market / industry | By topic dimensions: market definition → size and growth → structure and players → drivers and risks → outlook | PESTEL, Five Forces, 3C |
| Business / company strategy | Open with SCQA; chapters follow the argument's supporting points | SWOT, VRIO, value chain, 3C |
| Policy / regulation | Bardach eightfold path (see Layer 1) | Cost-benefit, stakeholder map, power-interest grid |
| Survey of practice / precedents ("how do fields handle X?") | By field or by the question's dimensions, then a cross-field comparison | Comparison table, issue tree |
| Problem / root cause | What → Where → Why → How | Fishbone (Ishikawa), 5 Whys, issue tree |
| History / past event | Chapters adapted from the historical method: background → sources → course of events → interpretations → significance | External / internal source criticism, timeline |
| Culture / society | Chapters adapted from a case-study report: context → case → analysis → lessons | Hofstede dimensions, thematic analysis, stakeholder map |
| Many scattered findings, no obvious shape | KJ method: group → label → relate → write up | KJ grouping, affinity table |

If the topic is unsettled (experts disagree, the situation is changing fast), map the positions and what would settle them instead of forcing one answer.

## Layer 1 — Skeletons

Order the chapters **after** the conclusion and TOC — the reader gets the answer first, then the chapters in skeleton order. Drop steps with nothing to say.

- **SCQA** (Minto): Situation → Complication → Question → Answer. Minto uses it for the opening; the body then follows the answer's supporting points.
- **空・雨・傘**: what is observed → what it means → what to do.
- **Problem-solving steps**: What (the problem) → Where (where it occurs) → Why (causes) → How (actions). For problems and root causes, not for describing a market.
- **Bardach eightfold path**: define the problem → assemble evidence → construct alternatives → select criteria → project outcomes → confront trade-offs → decide → tell your story. Bardach calls it iterative, not a fixed order.
- **Historical method** (research process): heuristics (finding sources) → criticism → interpretation → synthesis. The chapter order for a history note is in the Layer 0 table.
- **Case-study report**: why this case → the case → analysis → what generalizes. Adapted from Yin's linear-analytic report structure.
- **KJ method** (Kawakita): collect → group → label → relate → narrate.

## Layer 2 — In-chapter tools

| Purpose | Tools |
|---|---|
| Break an issue down | Issue tree / MECE, 5W1H, fishbone, 5 Whys |
| Outside environment | PESTEL, Five Forces, 3C |
| Inside an organization | SWOT, VRIO, value chain |
| Users and products | JTBD, Kano, customer journey |
| Evaluate options | Decision matrix, cost-benefit, bull / base / bear scenarios |
| People and power | Stakeholder map, power-interest grid |
| Sources and the past | External criticism (is the source authentic, who made it, when), internal criticism (is its content credible), timeline |
| Culture and qualitative material | Hofstede dimensions (culture comparison), thematic analysis (Braun & Clarke — reviews, interviews, comments), KJ grouping |

## Layer 3 — Principles and checks

**Principles that hold throughout**: every claim traces to a source; separate fact from opinion; spend the words on what matters most.

**Gap check** (Step 2) — ask of the angle list:

| Blind spot | Question |
|---|---|
| Time | How does this change over time, and when does the conclusion expire? |
| Second-order effects | How will others react; what re-balances? |
| Feasibility and reversibility | Who can block it, can it actually be done, can it be undone? |
| Base rates | What usually happens in similar cases? |
| Rival explanations | What else could explain this; what evidence would contradict it? |
| Evidence quality | Are the sources independent and current? |
| Unknown unknowns | If this turned out wrong a year from now, what would the reason be? |

**Checks on the finished note**: the nine checkpoints in SKILL.md Step 5; for a recommendation, also a pre-mortem (assume it failed — why?) and a key-assumptions list.

**Guardrail**: an empty gap check is an honest result. Running a checklist is not the goal; ticking cells without thinking adds nothing.
