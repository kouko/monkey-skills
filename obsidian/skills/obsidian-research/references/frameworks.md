# Frameworks by layer (obsidian-research)

Frameworks listed by **how they are usually used** in a research note, not by what they "are": the same framework can serve two layers (SWOT can be one chapter's tool or a whole note's skeleton). Pick what makes this topic clearer; never force a framework onto a topic.

## Layers 0–2 — Structure and in-chapter tools

Match the question type (layer 0). The skeleton (layer 1) orders the chapters **after** the conclusion and TOC; drop steps with nothing to say. The tools (layer 2) break down one chapter's issue.

| Question type | Skeleton (layer 1) | In-chapter tools (layer 2) |
|---|---|---|
| Explain a concept or technology | By topic dimensions: what it is → how it works → state of the art → limits → adoption | 5W1H, issue tree |
| Compare options / choose a tool | Options → criteria → per-criterion chapters → matrix → recommendation | Decision matrix, trade-off table |
| Decide / "should I…" | 空・雨・傘: what is observed → what it means → what to do; open with SCQA (Situation → Complication → Question → Answer — Minto's opening, not a whole-note order) | Decision matrix, bull / base / bear scenarios |
| Market / industry | By topic dimensions: market definition → size and growth → structure and players → drivers and risks → outlook | PESTEL, Five Forces, 3C |
| Business / company strategy | Open with SCQA; chapters follow the answer's supporting points | SWOT, VRIO, value chain, 3C |
| Policy / regulation | Bardach eightfold path: define the problem → assemble evidence → construct alternatives → select criteria → project outcomes → confront trade-offs → decide → tell your story (iterative, not a fixed order) | Cost-benefit, stakeholder map, power-interest grid |
| Survey of practice / precedents ("how do fields handle X?") | By field or by the question's dimensions, then a cross-field comparison | Comparison table, issue tree |
| Problem / root cause | What (the problem) → Where (where it occurs) → Why (causes) → How (actions) | Fishbone (Ishikawa), 5 Whys, issue tree |
| History / past event | Adapted from the historical method: background → sources → course of events → interpretations → significance | External source criticism (is the source authentic — who made it, when), internal criticism (is its content credible), timeline |
| Culture / society | Case-study chapters: context → case → analysis → what generalizes (to theory, not to a whole population) | Hofstede dimensions (comparing national averages across countries; never applied to individuals), thematic analysis (Braun & Clarke — reviews, interviews, comments), stakeholder map |
| Many scattered findings, no obvious shape | KJ method (Kawakita): one fact per card → group → name each group → arrange and relate the groups → write up | KJ grouping, affinity table |

If the topic is unsettled (experts disagree, the situation is changing fast), map the positions and what would settle them instead of forcing one answer.

## Layer 3 — Principles and checks

**Principles that hold throughout**: every claim traces to a source; separate fact from opinion; spend the words on what matters most.

**Gap check** (Step 2) — ask of the angle list:

| Blind spot | Question |
|---|---|
| Time | How does this change over time, and when does the conclusion expire? |
| Second-order effects | How will others react; what re-balances? |
| Feasibility and reversibility | Who can block it, can it actually be done, can it be undone? |
| Base rates | What usually happens in similar cases? |
| Rival explanations | What else could explain this; what evidence would contradict it? |
| Evidence quality | Are the sources independent and current? |
| Unknown unknowns (pre-mortem) | If this turned out wrong a year from now, what would the reason be? |

**Checks on the finished note**: the checkpoints in SKILL.md Step 5 and the citation check in Step 6.

**Guardrail**: an empty gap check is an honest result. Running a checklist is not the goal; ticking cells without thinking adds nothing.
