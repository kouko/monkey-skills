# Proposal — shift-scheduler

> **ARCHIVED (loom 1.0, 2026-09-02)** — this record was produced by `spec-expansion`, `completeness-critic` and their siblings, skills that no longer exist. It is kept as evidence of what they did, not as instructions for anything to run.

**Seed:** "Let a manager auto-generate a weekly staff schedule respecting
availability, skills, and labor rules."

Generated by loom-spec GENERATE (spec-expansion 3 phases) +
completeness-critic (loop-until-dry, 6 rounds, K=2). This is a spec **draft**,
not a finished spec. Coverage is stated relative to the seed and the lenses
applied; see the closing coverage statement. Trust is earned by execution
(loom-code's VERIFY gate), never by a draft that looks finished.

## USM backbone

Phase ① artifact — the happy-path user-journey spine (left-to-right ordered
steps the manager + system walk through). Each step tags the actor and the
objects/CTAs it touches.

| # | Step (CTA) | Actor | Objects touched | Provenance |
|---|---|---|---|---|
| 1 | Configure the planning unit (location, week, labor-rule profile, budget, demand forecast) | Manager | Schedule, LaborRule, Budget, DemandForecast | seeded (labor rules) / inferred (budget, forecast) |
| 2 | Collect inputs (staff availability, skills/certs, time-off, protected leave) | Employee → System | Availability, Skill, Employee, protected-leave | seeded (availability, skills) / critic-found (protected-leave) |
| 3 | Trigger auto-generate | Manager → SchedulingEngine | Schedule, Shift, Assignment | seeded ("auto-generate") |
| 4 | Engine solves: match eligible staff to shifts under hard + soft constraints | SchedulingEngine | Assignment, Shift, LaborRule, Skill, Availability | seeded |
| 5 | Engine returns outcome (feasible / partial / infeasible + explanation) | SchedulingEngine → Manager | Schedule, Assignment, infeasibility-reason | inferred / critic-found (explanation) |
| 6 | Review & adjust (manual override, manual fill of gaps, accept gaps) | Manager | Assignment, Shift, OpenShift | inferred |
| 7 | Approve & publish | Manager | Schedule | inferred |
| 8 | Notify staff; collect acknowledgement | System → Employee | Notification, Assignment | critic-found |
| 9 | Handle post-publish change (swap / give-away / pickup, manager edit) | Employee / Manager | SwapRequest, Assignment, Shift | inferred |
| 10 | Lock at cutoff; reconcile actuals; archive; export for payroll/audit | Manager / Payroll / Auditor | Schedule, TimeClock/actuals, audit-log | inferred / critic-found (actuals, audit) |

The seed names steps 1–4 (configure rules, collect availability/skills,
auto-generate). Steps 5–10 are inferred from rostering reality and the critic
loop — review/publish/notify/swap/lock/reconcile are the lifecycle the seed
silently assumes.

## OOUX object model

Phase ② artifact — the object inventory + each object's state machine.
Per-object ORCA fan-out was dispatched as parallel subagents (one per object,
disjoint work). Ten first-class objects survived.

### Inventory

| Object | One-line definition | Provenance |
|---|---|---|
| **Schedule** | Manager-owned weekly roster for one planning unit (location × ISO week), holding Shifts and Assignments. | seeded |
| **Shift** | A single bounded work slot (one role, time window, location) demanding a headcount. | inferred |
| **Employee** | A person engaged to work shifts; a schedulable resource with cost, capability, legal constraints. | seeded |
| **Availability** | A time-bounded declaration of when an employee can / cannot / prefers to work. | seeded |
| **Skill** | A qualification/certification gating who may be placed on a shift (held per-employee with expiry). | seeded |
| **LaborRule** | A declarative scheduling constraint (legal=HARD or org=SOFT), jurisdiction-scoped, effective-dated. | seeded |
| **Assignment** | The concrete employee↔shift binding the engine emits. | inferred |
| **SwapRequest** | A post-publish request to trade / give away / pick up a shift. | inferred |
| **DemandForecast** | The driver of `required_headcount` per shift (where the staffing target comes from). | critic-found |
| **Notification** | The delivery + acknowledgement record for publish/change events (gates the predictive-notice clock). | critic-found |

Supporting objects re-seeded by the critic (modeled as attributes/relations
rather than separate ORCA blocks, to keep the inventory tight): Budget,
CBA/union-rule, ShiftTemplate, OpenShift, On-call/standby, TimeClock/actuals,
break/meal-relief sub-shift, external-commitment accommodation.

### State machines

**Schedule**
```
Draft ──configure──▶ Draft ──generate──▶ Generating
Generating ──solver error/timeout──▶ GenerationFailed ──retry──▶ Generating
Generating ──no feasible solution──▶ Generated:Infeasible
Generating ──hard ok, gaps remain──▶ Generated:Partial   (understaffed slots)
Generating ──all hard satisfied────▶ Generated:Feasible
Generated:Infeasible ──relax constraints / edit inputs──▶ Draft
Generated:Partial ──manual fill / accept gaps──▶ UnderReview
Generated:Feasible ──────────────────────────────▶ UnderReview
UnderReview ──reject──▶ Draft
UnderReview ──approve──▶ Published
Published ──reopen (pre-lock correction, new version)──▶ Draft
Published ──swap / last-minute change (change_log appended)──▶ Published
Published ──un-publish before commitment cutoff──▶ Draft   (tracked retraction)
Published ──lock (cutoff / payroll freeze)──▶ Locked
Locked ──payroll ingested, period ends──▶ Archived
Locked ──emergency unlock (audited)──▶ Published
any ──discard──▶ Archived
```

**Shift**
```
Open/Unassigned ──assign (engine or manager)──▶ Assigned
Open/Unassigned ──headcount unmet at publish──▶ Open:Understaffed (→ Schedule:Partial)
Assigned ──employee confirms──▶ Confirmed
Assigned ──employee declines / manager unassigns──▶ Open/Unassigned
Confirmed ──request swap──▶ SwapPending ──approved──▶ Reassigned ─▶ Confirmed
SwapPending ──rejected / expired──▶ Confirmed (original holds)
Confirmed ──cancel──▶ Cancelled
Confirmed ──clock-in──▶ InProgress ──clock-out──▶ Completed
Confirmed ──start passes, no clock-in──▶ NoShow ──manager covers──▶ Assigned(cover)
NoShow ──no coverage found──▶ NoShow:Uncovered (terminal gap, audited)
```

**Employee**
```
Onboarding → Probation → Active
Active ⇄ OnLeave            (approved time-off / LOA / protected leave)
Active → Suspended ⇄ Active
Active/OnLeave/Probation/Suspended → Terminated   (terminal; rehire = new id)
```
Only **Active** is schedulable. OnLeave / Suspended / Terminated mid-published-week
→ existing future Assignments must be voided + re-filled, not silently kept.
Protected-leave (FMLA/parental/jury/medical) excludes from assignment WITHOUT
counting as a fair-distribution penalty.

**Availability**
```
NotSubmitted → Submitted → Approved → Expired
Submitted → Rejected → NotSubmitted (resubmit)
Approved → Superseded (newer Approved replaces)
Approved ──conflicts-with-approved-timeoff──▶ ConflictHeld
ConflictHeld → Approved (TOR cancelled) | → Superseded (TOR wins, window voided)
```
Late submission (`submitted_at > deadline`) → policy choice (treat as
no-availability vs fall back to last-Approved recurring pattern) — surfaced,
not silently chosen.

**Skill** (state lives on the per-employee holding, not the catalog row)
```
NotHeld → InProgress → Certified
Certified ──(expiry − notice_window)──▶ ExpiringSoon ──renew──▶ Certified
ExpiringSoon ──expiry passes──▶ Expired ──renew──▶ Certified
Certified/ExpiringSoon ──admin/board action──▶ Revoked
```
Schedulable predicate = `Certified ∨ ExpiringSoon` **at shift time** (not at
generation time). Hard block = `Expired ∨ Revoked ∨ NotHeld`. Verified vs
self-attested is a trust dimension orthogonal to state.

**LaborRule**
```
Draft → Active → Superseded → Retired
Active ──repealed / jurisdiction drops──▶ Retired
```
Effective status is `(rule × jurisdiction × date)`, not a global flag.
Lifecycle-Active with `effective_date > schedule.week` is **not yet enforced**.
Audit needs point-in-time rule resolution (judge a past roster by the rule
version then effective → keep Superseded for history).

**Assignment**
```
Proposed (engine) ──override──▶ Overridden (manager) [both carry source/audit ptr]
Proposed/Overridden ──confirm──▶ Confirmed
Confirmed ──modify──▶ Modified ──revalidate PASS──▶ Confirmed
Modified ──revalidate FAIL (hard)──▶ edit rejected, stays flagged
Confirmed ──cancel (mgr/giveaway)──▶ Cancelled
Confirmed ──worked──▶ Completed ─▶ Payroll | ──absent──▶ NoShow ─▶ Payroll (penalty)
```
Load-bearing invariant: **no roster mutation skips revalidate against
LaborRule + coverage** — engine placement, manager override, and approved swaps
all funnel through the same gate.

**SwapRequest**
```
Requested ──(targeted/open)──▶ PendingPeerAcceptance ──accept──▶ PeerAccepted
PeerAccepted ──(needs approval?)──▶ PendingManagerApproval ──approve──▶ Approved
PeerAccepted ──(no approval needed)──▶ Approved
Approved ──validate(rules+coverage) PASS──▶ Applied (old Cancelled, new created)
Approved ──validate FAIL──▶ Rejected
Terminal: Applied · Rejected · Expired · Withdrawn
```
Load-bearing edge: **manager approval is intent, not the final gate** — the
engine re-checks OT/min-rest/coverage at apply time; an approved swap can still
bounce to Rejected. Giveaways (net −1 headcount) are the understaffing-risk case.

**DemandForecast**
```
Absent → Provided → Applied(drives required_headcount) → Superseded
```
Absent forecast → engine refuses / flags (does not default headcount to 0/1).

**Notification**
```
Pending → Sent → Delivered → Acknowledged
Sent ──delivery fails──▶ Failed ──retry/escalate──▶ Sent
```
Predictive-notice / predictability-pay clock starts on **Delivered** (or the
jurisdiction's notice-of-record event), not on Published.

## Path × edge matrix

Phase ③ artifact. The cartesian grid `backbone × object × CTA × state`
over-generates (10 objects × ~6 CTAs × ~6 states × 10 steps ≈ thousands of
cells, most illegal). Below is the grid **after** pruning through the 7 lenses:
illegal cells dropped, surviving legal paths kept, and aspects the grid cannot
see surfaced by the system/NFR/policy lenses.

### Lens 1 — state-transition legality (paths kept / edges flagged)
- **Kept (legal happy paths):** Schedule Draft→Generating→Feasible→UnderReview→Published→Locked→Archived; Shift Open→Assigned→Confirmed→InProgress→Completed; Assignment Proposed→Confirmed→Completed; SwapRequest Requested→…→Approved→Applied.
- **Flagged as edge cases (legal but off-happy-path):** Generated:Infeasible (with explanation), Generated:Partial (gaps), Shift NoShow:Uncovered, Assignment Modified-revalidate-FAIL, SwapRequest Approved-validate-FAIL, Schedule un-publish/retraction, emergency unlock.
- **Dropped (impossible cells):** assign to a Terminated employee; Completed before clock-in; publish a Generating schedule; swap on a Locked/past shift; apply a SwapRequest that skips validate.

### Lens 2 — BVA (data edges)
zero employees · zero shifts · demand > total capacity (mathematically
infeasible) · employee at exactly `max_hours` (off-by-one `<` vs `<=`) ·
fractional hours toward a cap · negative/zero `required_headcount` · shift
crossing midnight / the week boundary (hours-attribution rule) · min-rest
across the week seam · cert expiring mid-week / mid-shift · availability for a
non-existent future week · 14-day-notice at 13d 23h (boundary of the notice
window).

### Lens 3 — CRUD completeness (per object)
- **Create:** Shift from template/forecast; Assignment by engine/manager; SwapRequest by employee; Availability by employee.
- **Read:** scoped reads (manager sees own location only; employee sees published only; cost/DOB hidden); Auditor/Regulator export.
- **Update:** override Assignment (must revalidate); reopen/un-publish Schedule; supersede Availability/LaborRule.
- **Delete:** cancel Assignment (may understaff Shift); discard Schedule; retention-purge/anonymize PII vs statutory min-keep.

### Lens 4 — permissions (who may perform each CTA)
RBAC matrix: only Manager/role-X may assign, override, approve, publish, lock;
Employee may set own availability, request swap, confirm, decline; engine may
propose/validate; Auditor/Regulator read-only export. Unauthorized-actor paths
(employee edits another's availability; shift-lead publishes; manager overrides
a *statutory* minimum) are rejected or require dual-control.

### Lens 5 — empty / error / loading states
empty: no availability submitted, no shifts, no eligible staff. error:
GenerationFailed (solver crash/timeout), infeasible-with-explanation,
revalidate-FAIL, notification-delivery-Failed. loading: Generating
(long-running solve), partial-write-in-progress (must be atomic / not surfaced
as a valid partial result).

### Lens 6 — NFR (system-layer aspects OOUX cannot reach)
performance/scale (solve latency for N employees × M shifts; documented
ceiling) · solver determinism (fixed seed → diffable re-run) · solver
time-budget/timeout (best-so-far + unproven-optimal flag) · concurrency
(optimistic-lock on concurrent manager edits; engine-while-edit;
concurrent-swap double-booking) · idempotent generate (dedupe double-trigger) ·
partial-write atomicity (all-or-nothing) · DST / multi-timezone (compute
rest/notice in UTC; normalize cross-TZ swaps) · privacy (cost, DOB are
sensitive) · audit log (append-only, who/what/when, predictability-pay
evidence) · observability (solve-time, infeasibility rate) · i18n (week-start
Sun vs Mon, locale, currency) · a11y (status not by color alone) ·
retention/erasure.

### Lens 7 — policy / legal
min-rest (EU WTD 11h) · weekly cap (FLSA OT >40h as pay-trigger; EU 48h avg) ·
minor youth-labor (school-hours, nightly caps) · mandatory meal/rest breaks
(coverage hole = relief assignment) · fair-workweek advance-notice +
predictability/reporting-time pay + clopening · minimum-staffing (e.g.
nurse-ratio) · CBA/union (seniority pick-order, distinct from law) ·
protected-leave (FMLA/parental/jury/medical) · disability modified-duty
accommodation · external-commitment accommodation (religious / court-order,
hard non-negotiable) · multi-jurisdiction rule selection (per location/person) ·
works-council co-determination approval · disparate-impact / discrimination
audit of auto-assignment · joint-employer / concurrent-employment aggregate
hours · co-presence / two-person / lone-worker relational coverage ·
schedule-as-external-contract SLA (franchisor/client/insurer) · statutory
record-keeping min-retention.

## Blind spots — needs human/field input

The critic's load-bearing output. These are gaps that **exist** but cannot be
closed by a generator/critic — the missing fact is real business/domain reality
that must come from a named human or field source. Naming the gap is first-class
output; inventing the missing value would be worse.

- **Actual jurisdiction(s)** — every legal threshold (min-rest hours, weekly cap,
  minor caps, clopening gap, predictability-pay schedule, holiday-pay rules,
  works-council applicability) is jurisdiction-specific. → *legal counsel per
  deployment site.*
- **Real legal retention windows** — GDPR/CCPA erasure maximum vs labor-law
  minimum-keep are opposing statutory numbers. → *legal / records-management.*
- **Weekly labor budget figure + pay-rate model** — to make the Budget ceiling a
  concrete hard/soft constraint. → *finance / ops.*
- **Whether a CBA/union exists and its clauses** — seniority guarantees, premium
  triggers, max-consecutive-days are contract text, not inferable. → *HR / labor
  relations.*
- **Solver objective weights** — the true business priority between labor-cost,
  preference-fit, and fairness. → *product / ops decision.*
- **Acceptable generation latency + scale ceiling** — the real distribution of
  employees × shifts × locations. → *field measurement, not a guessed SLA.*
- **Demand-forecast methodology** — how `required_headcount` is actually derived
  (sales model / footfall / manual). → *field interview with operations.*
- **Fairness metric + acceptable disparity threshold** — Gini vs variance, and
  the legal/ethical tolerance for protected-class disparity in auto-assignment.
  → *legal + ethics review.*
- **Notice-of-record event** — which timestamp (publish / delivered / acknowledged
  / first-view) legally starts the predictive-scheduling clock. → *counsel,
  jurisdiction- and case-law-dependent.*
- **Multi-site authority model** — for a shared employee, whether a "home"
  schedule has veto or first-come-wins. → *org policy.*
- **Override taxonomy** — which minimums are hard-illegal (never overridable) vs
  soft-policy (overridable with justification / dual sign-off). → *management +
  legal sign-off.*
- **ACA measurement method** — look-back vs monthly, and whether benefits-threshold
  crossings hard-block or only advise. → *HR policy.*
- **Joint-employer aggregate-hours handling** — declare-and-attest vs conservative
  cap vs explicit out-of-scope for concurrent/agency employment. → *legal +
  product scope decision.*
- **External-contract minimums** — franchisor/client/insurer staffing covenants
  are in contracts the engine has no feed for. → *contract review.*
- **Minor school-calendar source** — per-district session/holiday calendars have
  no canonical feed. → *external integration / data-source decision.*
